# 安全重构与防腐协议 (Safe Refactor Protocol)
> 适用于：对现有模块进行逻辑重构、结构优化、解耦拆分，或性能重写时。
> 核心目标：**杜绝平行实现、杜绝契约破坏、杜绝尸骸残留、杜绝改动越界**。

---

## 1. 重构范围与不变量 (Scope & Invariants)
- **重构目标模块**：`path/to/target.ts`
- **重构动机**：解决什么问题（如：嵌套过深、职责过载、重复逻辑抽离、性能瓶颈）。
- **对外不变量 (External Contract Invariants)**：
  - [ ] 函数签名、参数类型与返回值格式严格保持一致（或明确列出调用方全量迁移清单）。
  - [ ] 外部导出的公共 API 行为不变，不破坏任何现有调用方。
- **改动边界 (Blast Radius)**：
  - 允许改动文件：仅限 `path/to/target.ts` 及直接受影响的调用点。
  - 严禁触碰：除目标模块及其测试外，严禁对无关文件进行批量格式化、依赖升级或无关重命名。

---

## 2. 基线测试守护 (Baseline Test Guard - 安全网)
> **铁律：没有测试的重构就是制造未知的灾难。**
- [ ] **现存测试验证**：运行现有测试命令 `...`，确认全部通过（基线为绿）。
- [ ] **若无自动化测试（必须先立靶子）**：
  - 在修改业务逻辑前，先针对重构模块补充 1~3 个最小高频场景的基准测试（Characterization Test / Golden Master）。
  - 记录输入与期望输出，确保重构前后黑盒行为 100% 吻合。

---

## 3. 重构五戒 (The Five Refactoring Invariants)
1. **戒平行实现 (No Parallel Implementations)**：
   - 严禁创建 `ServiceV2.ts`、`newCalculate.ts` 等平行文件并存。
   - 必须在原模块或明确替换的单一目标中就地演进；若必须新建，必须在同一个原子改动中完成全量迁移并删除旧文件。
2. **戒注释尸骸 (Zero Commented Corpses)**：
   - 替换为新实现时，旧代码直接 git 物理删除，**严禁使用 `// old code...` 或 `/* 暂存 */` 注释残留**。Git 历史已有完整记录。
3. **戒过度工程 (Anti-Overengineering - 践行 `/simplify`)**：
   - 能用纯函数解决的不建抽象工厂或复杂继承；
   - 消除嵌套地狱：提炼 Early Return (卫语句)，将超过 3 层的嵌套展平；
   - 优先复用项目中已有的通用 Utils 和 Token，不私造临时工具函数。
4. **戒双写与状态分裂 (No Dual-State / Double Writes)**：
   - 严禁新旧逻辑各跑一遍、或在新旧两个 Store 中同时更新同一份数据。
5. **戒无验证提交 (Verified Transitions Only)**：
   - 每一个小步重构完成后，立即跑一次编译检查与基准测试，红了立刻就地修正。

---

## 4. 重构完成验收清单 (Definition of Done)
- [ ] 运行静态类型检查：`tsc --noEmit` 或项目类型检查通过，零新增警告。
- [ ] 运行测试套件：所有既有测试 + 补充的基准测试 100% 通过。
- [ ] 全局 grep 验证：被废弃的旧符号、旧函数在项目中已被彻底清除（零引用）。
- [ ] 零残存尸骸：没有留下未引用的死导入、无临时 debug 日志、无大块注释。
- [ ] 反哺免疫：提炼本次重构经验（如“状态一律收拢在 Store，禁止局部自建缓存”），询问写入 `CLAUDE.md`。
